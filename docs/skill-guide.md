# Skill 说明

## 适用范围

本 skill 面向嵌入式 C/C++ 的编写、修改、重构、排版和审查，关注风格、命名、注释、所有权、错误路径及 ISR/DMA/寄存器访问。芯片初始化顺序和 SDK 契约仍以工程代码与设备文档为准，缺少证据时应明确指出，不能自行编造 API、寄存器或时序要求。

它提供模型指令和工具配置，不能保证模型始终遵守规则，也不能用一次格式检查证明并发、时序或硬件行为正确。格式、编译、主机测试和硬件测试应分别报告，不把“考虑过”写成“已验证”。

## 分层执行

| 层次 | 内容 | 加载或执行时机 |
|---|---|---|
| `SKILL.md` | 范围、优先级、核心风格和路由 | skill 被调用后读取 |
| `references/` | 语言、硬件、注释和工具细则 | 一个语言分支，加所有相关主题 |
| 项目指令 | 项目接口、运行时政策和本地约定 | 使用宿主配置的项目入口 |
| `.clang-format` | 缩进、括号位置、空格和换行 | 新文件全量，旧文件按修改范围 |
| `.clang-tidy` | 显式诊断，包括缺少控制体大括号 | 先诊断，再审阅具体修复 |
| 构建及测试 | 行为、目标平台和硬件证据 | 使用工程真实命令 |

优先级为显式用户要求、适用项目规则和配置、邻近旧代码约定、个人默认值。头文件按编译环境判断语言；含 DMA 的 C 修改同时读取 C 与硬件规则，修改注释时再加入注释规则。纯排版不加载整套语义审查细则，已读取且未变化的配置在同一任务中复用。

## 风格和边界

默认四空格、不使用 Tab，函数左大括号在下一行，控制语句括号同行，`else`/`catch` 跟随前面的右括号。非空控制体加括号，每行一个可执行语句，不压缩普通函数体；有意的空循环、宏续行和格式敏感的数据表保持必要结构。

新文件和私有符号优先采用 `snake_case`，SDK、公有接口及原有类型保持稳定。协议、寄存器或 ABI 要求位宽时使用固定宽度整数，大小和容量采用适当的大小类型；不借风格修改迁移整套类型。注释说明契约、时序、所有权与原因，不复述显而易见的语句。

只审查时不改文件；只排版时不重命名、重构或调整 include 顺序。不为消除告警删除 `volatile`、对齐/段属性或同步操作，不擅自升级语言标准、引入依赖或改变错误处理政策。

## 工程模板和工具

模板是候选配置，不是安装后的全局设置。逐项合并到目标项目并保留现有约定。宿主对 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md` 的发现方式有所不同，采用已有项目入口即可，不必维护三份相同规则。

LLVM/clangd 版本可不同。缺少检查或选项时使用可执行部分并说明覆盖缺口，需要适配时使用本次运行的兼容配置；不强制升级，不关闭补全或导航。采用或排错时再读取 [tool-checks.md](../references/tool-checks.md)。
